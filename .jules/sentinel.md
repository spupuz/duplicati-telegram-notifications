## 2024-05-19 - [Prevent literal quote injection in bash parameter expansion]
**Vulnerability:** The HTML escaping function (`escapeHTML`) was vulnerable to injecting literal quotes across different shell environments and versions. In Bash parameter expansion (e.g., `${var//pattern/replacement}`), if the assignment is inside double quotes, wrapping the replacement string in quotes (e.g. `val="${val//</"&lt;"}"`) forces the quotes to be interpreted as literal characters. Additionally, Bash 5.2+ introduces `patsub_replacement`, where `&` acts as the matched text, leading to double-escaping vulnerabilities if not properly disabled.
**Learning:** Shell parameter expansion rules and options change between versions. The quote semantics inside string replacements differ depending on context and shell versions, which can lead to broken variables, malformed strings, or bypasses.
**Prevention:** Avoid wrapping the right-hand side replacement string with quotes when the variable assignment is already double-quoted (e.g., `val="${val//</&lt;}"`). Furthermore, disable version-specific parameter expansions like `patsub_replacement` (`shopt -u patsub_replacement 2>/dev/null || true`) for consistent and safe string escaping.

## 2024-05-15 - [Critical] Fix HTML Escaping and Asynchronous Alert Drop
**Vulnerability:** The `escapeHTML` function was malfunctioning due to incorrect quote usage and the introduction of `patsub_replacement` in Bash 5.2. Furthermore, critical security alerts were being sent via an asynchronous `curl` command `(curl ... &)`, leading to silently dropped notifications in ephemeral environments.
**Learning:**
1. In Bash parameter expansion `${var//pattern/replacement}`, quotes in the replacement string are treated literally. `&` has a special meaning in Bash 5.2+ (referencing the matched substring) when `patsub_replacement` is enabled, which broke HTML escaping.
2. In ephemeral environments (like Docker containers where Duplicati might run), running network requests asynchronously causes the parent process to exit before the request completes, dropping alerts.
**Prevention:**
1. Do not use quotes around replacement strings in parameter expansions. Use `shopt -u patsub_replacement 2>/dev/null || true` before literal string replacements involving `&`.
2. Ensure critical network alerts (`curl`) run synchronously in shell scripts to guarantee delivery.

## 2024-05-15 - [Critical Subshell DoS and Bash 5.2 Escaping Risks]
**Vulnerability:** The script suffered from two silent failure conditions. First, network calls were executed in a detached subshell `(curl ... &)`, which causes silent failure in ephemeral environments (like Docker containers) that terminate immediately after the main script exits. Second, HTML escaping in Bash 5.2+ generated invalid HTML tags (e.g. `<lt;`) because the `patsub_replacement` shell option treated unescaped `&` in replacement strings as the matched pattern, causing the Telegram API to return a 400 Bad Request and drop notifications. Finally, temporary file creation using `mktemp` in `/tmp` without user ID namespacing could lead to permission collisions in multi-user environments.
**Learning:** Micro-optimizations like detached subshells for network calls or native string replacements must be thoroughly tested against target deployment environments (ephemeral CI/CD runners, diverse Bash versions, shared host environments) as they can introduce subtle regressions that completely break the core functionality (security alerting).
**Prevention:** Always execute critical network notifications synchronously unless a dedicated background worker system is in place. Explicitly manage shell options (e.g. `shopt -u patsub_replacement`) when performing native string manipulation to ensure backward and forward compatibility. Namespace temporary files with user IDs (e.g. `$(id -u)`) and prefer user-specific cache directories (`$XDG_CACHE_HOME`) over global `/tmp`.
