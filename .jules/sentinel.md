## 2024-05-18 - HTML Parameter Injection via Unescaped Duplicati Result Variables
**Vulnerability:** In `notify_to_telegram.sh`, variables extracted from the Duplicati result file (like `RES_AddedFiles`) were embedded directly into the notification string for Backup and Restore operations without HTML escaping, even though `parse_mode=HTML` was enabled.
**Learning:** Telegram API returns a 400 Bad Request error if the text contains invalid or unescaped HTML tags. An attacker or anomalous data could inject `<` and `>` into these parsed string, causing the webhook notification to silently fail and drop the message, leading to a localized Denial of Service (DoS).
**Prevention:** Always escape every user-controlled or dynamically generated variable before combining it into a string that will be sent via an API endpoint requiring HTML formatted strings. Utilized existing `escapeHTML` bash function for file and folder variables in `getOperationBackup` and `getOperationRestore`.
