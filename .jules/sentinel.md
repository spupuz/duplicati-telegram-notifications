## 2024-05-19 - [Prevent literal quote injection in bash parameter expansion]
**Vulnerability:** The HTML escaping function (`escapeHTML`) was vulnerable to injecting literal quotes across different shell environments and versions. In Bash parameter expansion (e.g., `${var//pattern/replacement}`), if the assignment is inside double quotes, wrapping the replacement string in quotes (e.g. `val="${val//</"&lt;"}"`) forces the quotes to be interpreted as literal characters. Additionally, Bash 5.2+ introduces `patsub_replacement`, where `&` acts as the matched text, leading to double-escaping vulnerabilities if not properly disabled.
**Learning:** Shell parameter expansion rules and options change between versions. The quote semantics inside string replacements differ depending on context and shell versions, which can lead to broken variables, malformed strings, or bypasses.
**Prevention:** Avoid wrapping the right-hand side replacement string with quotes when the variable assignment is already double-quoted (e.g., `val="${val//</&lt;}"`). Furthermore, disable version-specific parameter expansions like `patsub_replacement` (`shopt -u patsub_replacement 2>/dev/null || true`) for consistent and safe string escaping.
